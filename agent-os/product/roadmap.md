# Product Roadmap

## Phase 1: MVP

- **העלאה:** קובץ אחד או ערימה (PDF, JPG, PNG, HEIC), עם מד התקדמות לכל קובץ.
- **צינור עיבוד ב-8 שלבים:** ingest → preprocess → split → classify → extract → normalize → validate → confidence.
  - ב-MVP כל עמוד הוא טופס.
  - החילוץ נעשה ב-Claude API עם tool use לפלט מובנה. ערך שלא כתוב או שאי אפשר לקרוא בכלל מוחזר כ-null.
  - **כתב יד** בעברית, אנגלית, ערבית ורוסית: הערך מוחזר בכתב המקורי ומסומן לבדיקה. שדה בכתב יד, ושם או ת.ז. שחזרו ריקים, נקראים שוב מחיתוך מוגדל של התמונה. ok רק אם שתי הקריאות תואמות.
  - ולידציה: ספרת ביקורת של ת.ז., תאריך תקין ולא עתידי, וגורם שולח מתוך רשימה סגורה (senders.yaml).
  - ביטחון: סף שמוגדר בהגדרות, ובדיקה כפולה שאפשר להפעיל ולכבות על שדות שאינם ok.
  - טופס שנכשל לא עוצר את הערימה. אפשר להריץ אותו שוב בכפתור "נסה שוב".
- **מסך בדיקה ותיקון:** טבלה עם תמונת הטופס בצד, סימון כתום לשדות שמחכים לבדיקה, סינון "רק לבדיקה", עריכה במקום (התיקון נשמר מיד בשרת) וזום וסיבוב של התמונה.
- **ייצוא לאקסל:** גיליון RTL. ת.ז. נשמרת כטקסט, תאריכים בפורמט DD/MM/YYYY, וערכים מרובים מופרדים בפסיק. אם נשארו שדות כתומים מוצגת אזהרה לפני הייצוא.
- **מחיקת ערימה:** מוחקת גם את הקבצים וגם את הרשומות.
- **מדידת דיוק:** `python -m eval.run` מול eval/ground_truth.csv (10–15 טפסים). הדוח כולל דיוק לפי שדה, שגיאות חבויות, שיעור סימון וריק שגוי.
- **בדיקות pytest:** נרמול, ת.ז., התאמת גורם שולח וייצוא.
- **הרצה בפקודה אחת:** `docker compose up`.

### קריטריוני קבלה
- העלאה של שני קובצי הדוגמאות בפעולה אחת מסתיימת בטבלה מלאה.
- כל 6 השדות מופיעים (שם מלא בשדה אחד), וכל המספרים המרכזיים ומספרי ההתחייבות נשמרים.
- שם ות.ז. בכתב יד נשלפים (לבדיקה) ולא נשארים ריקים.
- אין ערכים מנוחשים: ערך שלא נמצא נשאר ריק.
- ת.ז. עם ספרת ביקורת שגויה מסומנת לבדיקה.
- הגורם השולח הוא תמיד ערך מהרשימה הסגורה, או שהוא מסומן לבדיקה.
- תיקון שדה נשמר גם אחרי רענון.
- האקסל נפתח תקין.
- סקריפט המדידה מפיק דוח.
- `docker compose up` מרים את כל המערכת.

### שאלה פתוחה
האם קיים פורמט אקסל קבוע שהמעבדה עובדת איתו (סדר עמודות ושמות)? אם כן, ממפים אותו ב-export.yaml בלי לשנות קוד.

## Phase 2: Post-Launch

### 2א. משתמשים, הרשאות ודשבורדים (יעד: 28/10)

#### תפקידים

| תפקיד | יכולות עיקריות |
|---|---|
| פקיד/ת קליטה | העלאת טפסים, צפייה ברשומות שחולצו, תיקון שדות מסומנים, שליחה לאישור |
| מאשר/ת (בקרת איכות) | אישור או החזרה לתיקון, הערות על רשומה, טיפול בחריגות שהוסלמו, אישור מרוכז |
| מנהל/ת מעבדה | צפייה בכל הרשומות והדשבורדים, ייצוא Excel/CSV, הקצאת עבודה בין עובדים |
| מנהל/ת מערכת | ניהול משתמשים ותפקידים, הגדרת כללי ולידציה ושדות חובה, צפייה ביומן פעולות |
| גורם שולח חיצוני (אופציונלי) | העלאת טפסים ומעקב סטטוס בלבד, צפייה בטפסים שהוחזרו לתיקון |

הגורם החיצוני מרחיב משמעותית את היקף האבטחה, ולכן הוא נשמר להרחבה עתידית.

#### האזור האישי

**משותף לכולם:** פרטי משתמש, התראות, פעילות אחרונה, מסננים שמורים, העדפות תצוגה.

**פקיד/ת קליטה**
- התור שלי: רשומות שממתינות לתיקון, ממוינות לפי ותק
- רשומות שהמאשר החזיר אליי, עם ההערה
- סטטוס ההעלאות שלי (בעיבוד / מוכן / נכשל)
- סיכום יומי: נקלטו, תוקנו, נשלחו לאישור

**מאשר/ת**
- תור אישורים, עם סינון לפי רמת חריגה
- חריגות שהוסלמו אליי
- היסטוריית האישורים וההחזרות שלי

**מנהל/ת מעבדה**
- תמונת מצב של המעבדה (הדשבורדים למטה)
- עומס לפי עובד, עם אפשרות להקצות מחדש
- היסטוריית ייצואים

**מנהל/ת מערכת**
- רשימת משתמשים ותפקידים
- כללי ולידציה פעילים
- יומן ביקורת (audit log)

#### דשבורדים

**תפעול**
- צבר עבודה לפי שלב: כמה רשומות יש כרגע בכל סטטוס
- גיל התור: פילוח רשומות לפי זמן המתנה, עם הדגשת חריגות SLA
- תפוקה: טפסים ליום או לשבוע, ומגמה לאורך זמן
- זמן ממוצע מקליטה לאישור, ופילוח לפי שלב (איפה נתקעים)

**איכות החילוץ** (הכי מעניין לשופטים בהאקתון AI)
- שיעור דיוק אוטומטי: אחוז השדות שאושרו בלי תיקון ידני
- שדות בעייתיים: אילו שדות מתוקנים הכי הרבה (מפת חום)
- התפלגות רמת הביטחון של המודל מול שיעור התיקון בפועל, לכיול הספים
- שיעור החזרה לתיקון אחרי אישור ראשוני

**מקורות**
- חריגות לפי גורם שולח: מוסדות ששולחים לעיתים קרובות טפסים חסרים או שגויים
- סוגי חריגות נפוצים: שדה חסר, פורמט שגוי, כפילות, חתימה חסרה

**צוות**
- תפוקה ועומס לפי עובד (גלוי למנהל בלבד)

#### הערות מימוש
- **תשתית חובה:** טבלת `users` עם `role`, וטבלת `audit_log` שרושמת כל שינוי סטטוס וכל תיקון שדה (מי, מתי, ערך לפני ואחרי). כמעט כל הדשבורדים נגזרים ממנה, ולכן מוסיפים אותה כבר עכשיו.
- הרשאות כ-middleware לפי תפקיד, כדי לשמור על המודולריות.

#### סדר עדיפויות עד 28/10
1. פקיד/ת קליטה + מאשר/ת + מנהל/ת מעבדה
2. 3–4 דשבורדים: צבר עבודה, דיוק אוטומטי, שדות בעייתיים, זמן לאישור
3. מנהל/ת מערכת וגורם חיצוני רק אם נשאר זמן

### 2ב. הרחבות לצינור

כל הרחבה מתחברת לשלב קיים או נוספת כשלב חדש ב-pipeline.yaml:

| הרחבה | מתחברת ל |
|---|---|
| יישור ושיפור תמונה (OpenCV) | preprocess |
| פיצול חכם של PDF ארוך לטפסים | split |
| תבניות ופרומפט ייעודי לכל גורם שולח | classify, extract |
| OCR מקומי (Tesseract) כמנוע השוואה | extract |
| הדגשת מיקום השדה על תמונת הטופס | מסך בדיקה |
| למידה מתיקונים (דוגמאות בפרומפט) | extract |
| מצב פרטיות: טשטוש שדות או מודל מקומי | preprocess, extract |
| דשבורד דיוק לאורך זמן | eval |
| קליטה אוטומטית מתיקייה או מתיבת מייל | ingest |
| ייצוא למערכת המעבדה | export |

**מחוץ להיקף:** פריסה בענן, אינטגרציה עם מערכות המעבדה. (משתמשים והרשאות עברו ל-2א.)
